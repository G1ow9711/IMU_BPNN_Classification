# 软件完成性验收报告

## 1. 验收边界

本报告对应 2026-07-15 的无硬件软件终验。独立源码审计发现的软件缺口均已修复，第二轮统一全量自动门通过；本报告是当前软件状态的最终验收记录。

本次没有开发板，不执行烧录、真实屏幕/触摸、QMI8658、AXP2101、PCF85063、马达、BLE 射频、电流、唤醒或长时间稳定性测试。软件通过不等于硬件通过。

## 2. 唯一全量入口

在仓库根运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\verify_software.ps1
```

正式终验不得使用 `-SkipIdfBuild`。成功总标志固定为：

```text
SOFTWARE_VERIFICATION_OK hardware_validation=not_run_no_hardware
```

验证临时文件、NuGet 缓存、dotnet 状态和 C harness 均写入项目本地 `.codex-local`，不会把运行缓存写入用户配置目录。

## 5. 用户后续真板验收清单

1. 按 `esp32/README.md` 建立串口并烧录 ESP32-S3 镜像。
2. 验证 410×502 AMOLED、触摸首击唤醒、启动/关机动画及 13 个生产状态。
3. 验证 QMI8658 25 Hz 重采样、真实推理平均小于 100 ms、最差小于 480 ms。
4. 验证每次有效计数只振动一次；30 ms、75%、5 kHz 马达波形不产生二次假计数。
5. 验证 AXP2101、PCF85063、15%/8%/5% 电量门槛、WOM、触摸/RTC 唤醒和真关机。
6. 验证 BLE 加密绑定、MTU23 与协商 MTU、弱信号、断线恢复、命令 1～11、Raw Stream 和一小时连接稳定性。
7. 验证 LittleFS 掉电恢复、可选 TF 拔卡和历史补传幂等。
8. 使用厂家原配 400 mAh 电池分别测全亮、熄屏连接、Deep-sleep 和训练占空比；不得用软件预算代替电流实测。
9. 连续运行一小时，检查任务栈高水位、内部堆、温升、重启、NaN 和内存下降。

## 6. 结论

计划要求的无硬件软件设计与自动验证已经完成。统一终验结果为 `SOFTWARE_VERIFICATION_OK hardware_validation=not_run_no_hardware`：Python 89 项测试、12 组 ESP32 主机测试、C/Python 双 M0 数值一致性、Windows 上位机 Release 构建、四组 C# 标志测试、216 文件注释审计和 ESP-IDF 整机链接全部通过。

动作识别运行时现使用准备态与运行态共用的整段证据累计器；分类不一致时暂停次数与相位推进，但训练时长和热量继续累计，开始、恢复、间隙与重置事件会清理旧证据。中文 LVGL 会先呈现可见界面，随后把传感器、存储或领域错误路由到错误页。BLE 六位配对码、成功、失败、断开、超时、停止和忘记设备状态均有明确中文反馈。AMOLED 与 FT3168 已接入真实显示开关及触摸休眠/唤醒顺序。

本报告不代表真板通过。真实屏幕、触摸、传感器、PMIC、马达、BLE 射频、电流、唤醒和长时间稳定性仍需在厂家原配硬件与电池上完成第 5 节验收。
