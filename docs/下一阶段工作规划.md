# 健身手柄下一阶段工作规划

## 1. 当前冻结基线

日期：2026-07-18。

当前阶段只冻结已经取得真板证据的链路，不把尚未执行的产品功能写成已通过：

- AMOLED 中文界面持续显示，文字重影已由真板确认消失。
- 自动熄屏、Light-sleep、Deep-sleep 和 PMIC 自动关机继续禁用。
- BLE 使用固定联调 PIN `123456`，保留绑定、MITM 和 LE Secure Connections。
- Windows 上位机可扫描附近设备、选择 `BPNN-FIT-*`、配对并建立 GATT 连接。
- QMI8658 原始六轴链达到 25 Hz；上位机显示加速度、角速度、采样率和数据质量曲线。
- 真机复核得到 `Connected=True`、MTU 256、校验错误 0、分片错误 0。
- 当前板内应用大小为 1,350,592 字节，SHA-256 为 `18FE3C3C1EBB5AFE2F2BB15CC358BA48F0DDBBCDB3BF17F581FD69A0D6F5DB48`。

当前源码比板内镜像多一项安全改进：重复配对时只删除当前对端绑定并返回重试。该改动已通过固件源码合同和 BLE 主机测试，但尚未重新烧板；应随下一版功能固件一起验证，不能视为当前真板已通过。

## 2. 总体顺序

后续严格按以下依赖顺序推进：

1. 297 维特征与双 M0 分类真板链。
2. 动作相位、次数、步数、时长和振动。
3. 训练会话、热量、历史和断线补传。
4. BLE 重连、重复配对和长稳。
5. 分级恢复低功耗。
6. 发布与恢复包。

任一阶段未通过，不提前启用下一阶段；尤其不能在分类、BLE 和 UI 未稳定时恢复自动低功耗。

## 3. 阶段一：297 维特征与双 M0 真板分类

### 实施范围

- 保持当前显示、QMI8658、RawStream 和 BLE 数据面不变，只恢复特征提取与双 M0 推理任务。
- 固定原始六轴顺序为 `gx、gy、gz、ax、ay、az`，采样率固定 25 Hz。
- 在诊断页增加当前动作、融合置信度、两个 M0 的 Top-1、推理耗时、窗口序号和异常计数。
- 上位机可选择保存带标签的真板窗口，生成后续混淆矩阵和阈值校准数据。

### 硬门

- 原始流保持 25 Hz，时间戳单调，校验错误和分片错误为 0。
- 297 个特征均为有限值；特征顺序、类别顺序、模型 SHA 和 Manifest 完全匹配。
- Python/C 特征最大绝对误差不高于 `1e-4`；双 M0、融合和动作段 logits 最大误差不高于 `1e-3`。
- 连续运行期间不出现任务创建失败、看门狗、堆下降失控或 COM 端口重枚举。
- 先证明分类结果能够从真板到达中文上位机；真实准确率在采集足够的逐类动作后单独评估，不用少量演示样本虚报。

## 4. 阶段二：动作相位、计数与振动

### 实施范围

- 8 类重复动作使用相位状态机计数；`walk/trot` 统计步数；`sit` 统计持续时间。
- 每次有效重复动作只产生一个 `MetricEvent`，由同一事件驱动 UI、BLE、存储和振动，禁止各模块重复计数。
- 重复动作每次有效计数振动 30 ms；`walk/trot` 每 10 步振动一次；`sit` 不振动。
- 马达真实导通前后登记 IMU 污染窗，排除触觉反馈造成的假峰。

### 硬门

- 每类动作形成逐次人工标注视频或人工按键真值，并输出误计、漏计和重复计数。
- 一次完整相位只能产生一次计数；暂停期间不计数、不累计热量。
- 振动队列拥塞只允许丢触觉反馈，不得回滚已经确认的计数。
- 输出逐类混淆矩阵、召回率和计数误差；弱类未达到目标时只校准该类，不改动已稳定类别。

## 5. 阶段三：会话、热量与历史

### 实施范围

- 恢复开始、暂停、继续、停止、总结和训练目标流程。
- 由设备统一计算次数、步数、持续时间和卡路里；上位机只展示设备权威状态。
- LittleFS 原子保存摘要；断线后按 `session_seq` 分页补传，重复请求保持幂等。
- 验证体重、目标、亮度、振动和开发者 RawStream 配置的 NVS 持久化。

### 硬门

- 断电恢复后最近完整摘要可读，半写记录不会被当成有效会话。
- 同一事件不会在 UI、BLE、历史或上位机中重复累计。
- 设备摘要、上位机历史详情和 CSV 导出字段一致。

## 6. 阶段四：BLE 可靠性与长稳

- 真板验证当前源码中的重复配对修复：只删除当前对端绑定，不清除其它合法绑定。
- 覆盖首次配对、已绑定重连、忘记设备、错误 PIN、断线重连、Windows 蓝牙关闭再开启和设备重启。
- 运行至少 1 小时 RawStream 与分类联合长稳，记录 RSSI、MTU、重连次数、丢包、校验错误、堆最小值和任务栈余量。
- 联调固定 PIN 在发布前改为随机显示码或产品安全策略；不得把 `123456` 当量产默认值。

## 7. 阶段五：分级恢复低功耗

必须最后执行，每级单独构建、烧录和验收：

1. 仅降低 AMOLED 亮度。
2. 无操作后关闭面板，但保持 BLE 和训练状态。
3. Light-sleep，验证触摸和 RTC 唤醒。
4. Deep-sleep，验证 QMI8658 WOM 唤醒。
5. 5% 电量保存摘要后由 AXP2101 安全关机。

每一级都要验证 POWER/BOT、USB 枚举、BLE 重连、界面恢复和状态不丢失；任何一级复现黑屏、循环重启或 COM 掉线，立即回退到上一稳定镜像。

## 8. 阶段六：发布与恢复

- 固定 ESP-IDF、BSP、LVGL、面板、触摸和 `dependencies.lock` 版本。
- 输出四段固件地址、长度、SHA-256、烧录脚本和厂家恢复固件路径。
- 输出 Windows 自包含上位机、版本清单、协议版本、模型 Manifest 和中文使用说明。
- 完成真板回归表后再标记发布；软件主机测试不能替代 AMOLED、触摸、BLE 射频、IMU、振动、功耗和长稳真板证据。

## 9. 下一次开始点

下一轮只做阶段一：恢复 297 维特征和双 M0 推理，把分类结果、置信度和推理诊断送到中文上位机。计数、振动、会话和低功耗保持关闭，避免同时引入多个变量。
